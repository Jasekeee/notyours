Fails closed

A crash, an invalid boundary, a replay that errors or a server older than your code blocks the stop. None of them counts as a pass.

Agent can't edit the tests

The guard hook blocks the agent's edits to locked boundaries, Kane recordings, run results and config. A guardrail for a cooperating agent, not a sandbox.

notyours: tests and boundaries are read-only for the agent.

Restarts your app before judging

Once a person approves the start command on this machine, the Stop hook restarts your app first, so a replay never judges old code.

app: { start: "node server.js", port: 3000 }

Catches edits made from the shell

sed -i, scripts and codegen don't fire edit hooks. Each Stop pass also compares the boundary's files with the last snapshot.

// how it works

Map it, prove it, lock it, guard it.

Real browsers, real sign-ins, and a verdict rule that gives the same answer on every replay.

  1. 01

    Map

    notyours map scans Express and Next.js routes and writes draft boundaries. You, or /notyours-map in Claude Code, finish them.

    GET /notes/:idGET /api/notes/:idPOST /api/export↓ .notyours/boundaries/_draft_*.yaml
  2. 02

    Prove

    Kane signs in as Alice and Bob in separate Chromes. Alice's record carries a canary token; Bob visits it. The token decides.

    Acreates NY-ALICE-…↓ Bob opens /notes/1001Bdid the token reach Bob?
  3. 03

    Lock

    notyours lock turns each proven boundary into a recorded Kane test. Later checks replay it, with no authoring runs.

    .notyours/tests/b1-…_bob_test.md↓ replayauthoring runs: 0passing replay: 0 credits
  4. 04

    Guard

    The Stop hook replays changed boundaries each time the agent tries to finish. A leak blocks the stop and hands the agent the evidence.

    agent stops↓ replay b1, b2, b4LEAK → exit 2, keep workingHELD → exit 0, done
// verdicts

Four verdicts, one rule.

Every probe also checks that the owner and the viewer can see their own tokens. A probe that couldn't have found anything doesn't count.

LEAK visible

The owner's token appeared in the viewer's rendered page.

LEAK in payload

The token reached the viewer's browser in a network response, even though the page didn't show it. Anyone can open DevTools.

HELD

The viewer never received the owner's token, and both positive controls passed.

HARNESS

A positive control failed, so the probe proves nothing. It is never counted as a pass.

Kane's pass/fail never decides; the token does.

// honest limits

What it checks, and what it doesn't.

notyours checks the boundaries you declare, in the running app. It isn't a penetration test.

Catches

  • One user's data on another user's screen, such as Bob opening Alice's note.
  • Data in a response the page doesn't render, such as JSON, scripts and downloads.
  • Signed-out guests reaching signed-in data.
  • Free users getting a paid feature through a plan gate that only hides the button.
  • A sweep of every page for anything another user created.
  • A regression your agent introduces in a locked boundary's code, before it reports the task done.

Doesn't

  • Anything you didn't write a boundary for. It isn't a scan of your whole app.
  • Logins other than email and password. No CAPTCHA, OAuth-only, SMS or authenticator codes.
  • Tokens inside images or PDFs. It reads DOM text and network bodies.
  • Code a boundary's surface doesn't list. Shared middleware is replayed only when a listed file changes.
  • Database policies. It sees what your app returns to a browser, not your RLS rules.
  • Hosts other than localhost, unless you pass --allow-host and confirm.

// faq

Questions.

Does it need an AI API key?

No. Kane drives the browsers, and the verdict comes from the canary token. Nothing is judged by an AI.

What does it cost?

Kane credits from your TestMu AI account. Measured: the quick demo used 61.69 credits (4 min 48 s), and a replay of four locked boundaries used 3.4 credits (170 s). run --dry-run prints an estimate without starting Kane, and the CLI caps authoring runs per project per day (default 20).

Does my data leave my machine?

Your app runs on localhost. Kane runs are tied to your TestMu AI account, and its evidence packs hold your account email and share links. init keeps them out of git; don't publish them.

Which frameworks does it understand?

The route scan reads Express and Next.js code. Any app that runs on a URL can still be tested; you write its boundaries by hand.

Can my coding agent cheat?

The guard hook blocks the agent's edits to locked boundaries, recordings, run results, budget and config, and the Stop hook fails closed. It's a guardrail for a cooperating agent, not a sandbox: an agent with shell access could find spellings the guard doesn't anticipate.
