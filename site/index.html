An agent can't finish a change that leaks.

Each edit marks the locked boundaries it could affect as dirty. When the agent tries to stop, notyours replays them as the other user. A leak sends the agent back with evidence.

How the verdict works

Every boundary ends in one of four verdicts. The owner's token is the only evidence.

  • LEAK visible

    The owner's token appeared in the viewer's rendered page.

  • LEAK in payload

    The token reached the viewer's browser in a network response, even though the page didn't show it.

  • HELD

    The viewer never received the token, and both positive controls passed.

  • HARNESS

    A positive control failed, so the probe proves nothing. Never counted as a pass.

Kane's own pass/fail never decides; the token does.

What a coding agent can't do

The checks live outside the agent's reach, or the agent is stopped.

  • Edit its own tests

    The guard hook blocks edits to locked boundaries, recordings, run results and config.

  • Raise its budget

    The daily cap on authoring runs (default 20) can only be changed by a person. Coding agents are refused.

  • Get past a broken guard

    The Stop hook fails closed. If the guard can't start, it blocks with "notyours guard unavailable".

It's a guardrail for a cooperating agent, not a sandbox.

What it catches, and what it doesn't

Measured on the bundled demo app, which has three seeded bugs. Kane CLI 0.10.0.

Catches

  • Bob opens Alice's note LEAK
  • Free user gets the Pro export LEAK
  • Guest opens notes HELD
  • Bob sweeps the note list HELD

Doesn't

  • Anything you didn't write a boundary for
  • CAPTCHA, OAuth-only and SMS logins
  • Tokens inside images and PDFs
  • Database policies: it tests what the running app returns
  • Hosts other than localhost, unless you allow them
  • Replays need fixed URLs on kane-cli 0.10.0
